# 周转筐领用与回筐核销台

- 行业：物流
- 技术栈：React、Vite、TypeScript、dnd-kit、zustand
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 数据：浏览器 localStorage（key：`hxwlfront-14-basket-desk-v2`），无新增依赖

## 业务闭环

1. **补录**：待分配订单补录配送时段（早/午/晚）、冷筐数、常温筐数；温区由筐数派生（冷链 / 常温 / 混温）。
2. **拖拽排车**：订单只能拖入与自己时段一致的司机格。系统按"同一司机 + 同一时段"校验：
   - 冷筐占用（在途 + 待回收）不超过冷筐车载额度；
   - 常温筐占用不超过常温筐额度；
   - 冷筐 + 常温筐合计不超过车辆总容量。
   - 任一冲突**整次拒绝**：不写状态、卡片留在原处、表单/弹窗输入保留。
3. **改派**：规则计算时先排除订单自身（=先释放原额度），再按目标格重算；已排车可拖回待分配池。
4. **发车锁定**：整格发车后司机、时段、筐数冻结，卡片不可再拖，只能送达核销。
5. **送达登记**：登记实回冷筐/常温筐与其中破损数。短少（领用 − 实回）与破损转入**待回收**，继续占用该司机同时段额度；在待回收面板**补录原因后才释放**。
6. **核销冻结与更正**：核销记录（含每个版本的实回/破损/说明）冻结不可改；"更正"追加新版本，原版本未处理回收项自动置为"已被更正替代"并停止占额，已释放的历史保持不变。
7. **刷新一致**：订单、司机额度、回收记录、核销版本同存于一个状态树/一个 storage key，每次变更原子落盘，刷新后同源一致。

## 分层

- `src/data.ts`：资料层——时段、司机车载额度、种子数据、存储键。
- `src/rules.ts`：判定层——纯函数，额度占用、排车/发车/核销/更正校验，不碰存储与 UI。
- `src/store.ts`：存储层——zustand 状态树 + localStorage 落盘 + 全局提示。
- `src/types.ts`：领域模型。
- `src/components/*`、`src/App.tsx`：页面层——dnd-kit 拖拽看板、表单、弹窗、待回收与核销台账。
